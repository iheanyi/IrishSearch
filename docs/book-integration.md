# IrishSearch → SpineFind course materials

Checked October 13, 2026. This is an implementation proposal, not an enabled integration. `bookr` is the local Rails source for SpineFind; links to its source below are pinned to commit `2fbf0509` so the claims can be rechecked after that project changes.

## What exists today

- IrishSearch reads Notre Dame's public PATH section details. It accepts a `books_link_html` anchor only when it points to `https://nd.bncollege.com/`; the PATH response does **not** supply ISBNs to the app. In 68 sampled public ND sections across Fall 2024, Fall 2025, Spring 2026, and Fall 2026, `books_link_html` was empty. The current [repository](../app/src/main/java/com/iheanyiekechukwu/irishsearch/CatalogRepository.kt) and [README](../README.md) therefore cannot rely on PATH to populate a course book list.
- SpineFind has a public `/book/:id` landing page, `/batch?isbns=...`, and `/lists/:public_id` pages, plus `/api/v1/books`, `/api/v1/prices`, `/api/v1/links`, and `/api/v1/lookups` endpoints. These are ISBN oriented. The implemented [routes](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/config/routes.rb) and [schema](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/db/schema.rb) have no university, term, course, or course-book mapping. The course API described in [SPEC.md](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/SPEC.md) is a plan, not a route currently serving data.
- SpineFind can create a shareable ISBN list through [`ListsController#create`](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/controllers/lists_controller.rb). Its response contains both a public URL and an edit-token URL. A mobile handoff should open only the public URL; the edit token is a capability and must stay private. The list and batch views obtain metadata from Open Library and show AbeBooks prices and retailer links ([list controller](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/controllers/lists_controller.rb), [metadata service](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/services/book_metadata_service.rb)).
- The SpineFind browser extension has a [BNCollege parser](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/extension/src/content/parsers/bncollege.ts) that extracts ISBNs from an **already rendered bookstore page**. It does not fetch a Notre Dame course's materials from a course code or CRN, and cannot run as that browser extension inside IrishSearch. SpineFind's B&N course-finder API notes are research with some steps explicitly inferred, not an implemented importer ([SPEC.md, Bookstore API Research](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/SPEC.md#bookstore-api-research-verified-january-2026)).

## Verified Notre Dame bookstore path

These observations came from public browser sessions and a controlled Chrome request trace on October 13, 2026. They establish a possible source of course ISBNs, subject to access and permission checks before automating it.

1. [NOVO Browse Classes](https://bxeregprod.oit.nd.edu/StudentRegistration/ssb/term/termSelection?mode=search) exposes a section-specific **Bookstore Links** tab. Its `TBListView` URL contains a `courseXml` value with university term, department, course number, and section, **not an ISBN**. For Spring 2026 CSE 10101/01, the XML identifies `202520 / CSE / 10101 / 01`; for Fall 2026 CHEM 10171/01 it identifies `202610 / CHEM / 10171 / 01`.
2. The browser's `GET /webapp/wcs/stores/servlet/TBListView?...` received HTTP 302. Spring 2026 CSE 10101/01 redirected to `/course-material-listing-page?utm_campaign=storeId=84429_langId=-1_courseData=CSE_10101_01_202520...`. The page then made `GET /course-material-caching/course?campus=8442&term=8442_1_26_W&course=8442_1_26_W_200_10101_1&section=01&oer=false` (HTTP 200). The returned HTML fragment displayed **Course Materials Selection Pending** and `Professor HUGHES`.
3. The Fall 2026 CHEM 10171/01 legacy link redirected instead to `/course-material/course-finder?...courseData=CHEM_10171_01_202610...` and showed **Term is not mapped**. This does **not** mean its books are unavailable: manually selecting Fall 2026 → CHEM → 10171 → 01 in the current finder displayed one required Pearson item, ISBN-13 **9780138081263**, and `Professor KESSLER`. Its course fragment was independently reachable in the browser at `GET /course-material-caching/course?campus=8442&term=8442_1_26_F&course=8442_1_26_F_150_10171_1&section=01&oer=false` and included the ISBN, required status, and instructor in HTML. The listing marked this digital material as **included in the course**, so a comparison link must not imply that the student needs to purchase another copy.
4. On initial load, the finder requested `GET /course-material/findCourse?courseFinderSuggestion=SCHOOL_CAMPUS&oer=false` and then `GET /course-material/findCourse?courseFinderSuggestion=SCHOOL_TERM&campus=8442&oer=false`. The latter returned JSON codes `8442_1_26_F` (Fall 2026) and `8442_1_27_W` (Spring 2027). The current manual listing URL, `/course-material-listing-page?bypassCustomerAdoptions=true`, contains no course identifier and depends on browser selection state. A direct CLI GET of the finder received an Akamai HTTP 403 while a fresh Chrome browser navigation received HTTP 200; changing the CLI User-Agent alone did not resolve it. The exact challenge rule is unverified. Browser request headers included Chrome client hints, fetch metadata, and browser transport behavior; copying those values into a mobile client has not been shown to work.
5. Other current finder examples yielded **No Course Materials Required** (Fall 2026 CSE 10001/01) and **Course Materials Selection Pending** (Fall 2026 CHEM 10101/01). These are separate from a request failure or a parser that found no ISBN. The sampled bookstore instructor labels were **surnames only**. The public NOVO result and class-details view for Fall 2026 CHEM 10171/01 (CRN 11745) did not provide an instructor name either. Do not show the surname as a course instructor or expand it using a faculty directory match; neither establishes the full name for that term and section. Add an instructor field only when a reliable section-specific source supplies the full name.

The course-specific cache response is an HTML fragment, not a documented public JSON API. BNCollege's mapping IDs (`8442_1_26_F_150_10171_1`) are distinct from ND's `202610` term and PATH's section CRN. The finder or its network responses must supply that mapping; string construction from a course code alone would be brittle. We have not verified direct Android/OkHttp access, Android WebView access, or an automation license for these endpoints. Do not ship a header spoof or challenge bypass as an integration.

## Recommended handoff

1. Keep a bookstore handoff for students. If PATH provides a trusted ND bookstore URL, use it, but handle the legacy **Term is not mapped** result. When PATH has no URL, the public [course finder](https://nd.bncollege.com/course-material/course-finder) is still a useful fallback. Do not fabricate ISBNs or imply a course-to-book match.
2. If a student supplies one or more ISBNs, normalize and checksum-validate them, then open SpineFind's existing `/book/:isbn` or `/batch?isbns=...` in the external browser. For a durable, shareable list, call `POST /lists` only after an explicit user action and open its public URL. A plain browser handoff does not need an IrishSearch account or a permanent app-to-site identifier.
3. For automatic course books, validate permitted access to the observed finder and course-fragment requests in the intended Android or server runtime, including term/department/course/section lookup. Parse the returned HTML within the exact section container, normalize and checksum-validate ISBNs, deduplicate variants, and retain required/recommended, included-in-course, pending, and no-materials states. Keep course key, source URL, and observed-at time; refresh when bookstore terms or adoptions change. If a server is needed, expose a course-materials lookup keyed by campus, term, course, and section. No such SpineFind endpoint exists yet ([current routes](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/config/routes.rb)); the existing `/batch?isbns=...` page can already receive a verified ISBN set.
4. Treat a student's saved schedule as private local data. Send only the selected course identifiers needed for a requested material lookup, or ask before uploading a whole schedule. A shareable SpineFind list should contain ISBNs, not the student's course history. Update IrishSearch's privacy text before enabling any server requests; currently it says class searches go directly to Notre Dame and there is no IrishSearch server ([README](../README.md), [privacy policy](../PRIVACY.md)).

## Amazon rules that affect the design

- The current [Associates policies](https://affiliate-program.amazon.com/help/operating/policies) permit links in an **Approved Mobile Application**, subject to Amazon's separate evaluation, free access, original content, and no Amazon pages in a WebView. A direct Amazon affiliate link or Amazon Product Advertising Content inside IrishSearch would need that approval. A normal user initiated link from IrishSearch to SpineFind's own website is a different flow; Amazon Special Links would be shown on SpineFind's site, subject to its own Associates account and policy compliance. Amazon's [mobile guidance](https://affiliate-program.amazon.com/help/node/topic/GHBY6W8UPTEFD3ZX) says to register app store URLs and avoid redirect URLs in an approved app.
- Amazon defines an ineligible **Redirecting Link** as one that sends a user through an intermediate site to Amazon without another affirmative action there. It also bars obscuring the referring site or making the Amazon destination unclear ([Commission Income Statement and Participation Requirements](https://affiliate-program.amazon.com/help/operating/policies), [automatic redirect FAQ](https://affiliate-program.amazon.com/help/node/topic/GVFBVT6N73NTC933)). SpineFind currently renders a page with an Amazon button, but that button's generated `/go/amazon?isbn=...` URL performs an immediate redirect ([view](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/views/books/show.html.erb), [redirect controller](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/controllers/redirects_controller.rb), [link service](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/services/affiliate_link_service.rb)). Before relying on Amazon commissions, replace that hop with a clearly labeled, direct tagged Amazon link from the SpineFind page, or obtain explicit program guidance on the redirect. A tap in IrishSearch must never silently bounce through SpineFind to Amazon.
- SpineFind must clearly disclose its Associate relationship and affiliate links ([Operating Agreement §5](https://affiliate-program.amazon.com/help/operating/agreement), [Amazon disclosure guidance](https://affiliate-program.amazon.com/help/node/topic/GHQNZAU6669EZS98)). The current list page has a disclosure; check every page where Amazon links appear and place a conspicuous disclosure near the link.
- If SpineFind later uses PA API or Creators API prices/images, the [IP license](https://affiliate-program.amazon.com/help/operating/policies) limits caching, requires timestamps/disclaimers for price or availability in specified cases, and bars client caching of Product Advertising Content. The policies also restrict price tracking and alerts unless Amazon agrees. Do not mix Amazon API content into cross-retailer product promotion. The existing [price endpoint](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/controllers/api/v1/prices_controller.rb) currently returns AbeBooks prices, while its Amazon price fetcher uses PA API only when configured ([source](https://github.com/iheanyi/spinefind/blob/2fbf0509d81b27b8a0398ea2842abb142fa78f13/app/services/price_fetchers/amazon.rb)).

## Decision point

The browser proof establishes course-to-ISBN lookup for one current section, but the legacy integration is inconsistent and the CLI HTTP client received an access challenge. Prototype a permitted, reliable lookup and verify several current/older sections before enabling auto-population. The existing SpineFind `/batch` route needs no new endpoint once ISBNs are known. A live reachability check of `spinefind.co/batch?isbns=9780138081263` timed out on October 13, 2026, so confirm the destination works before offering the handoff in the app.
